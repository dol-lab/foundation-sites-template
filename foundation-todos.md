# foundation-sites-template: work plan

Repo: `web/app/plugins/spaces-markup/vendor/dol-lab/foundation-sites-template` (its own git repo, `origin` = `dol-lab/foundation-sites-template`). Consumer: `spaces-markup` (composer `dev-master`). Finished phases are in git history; lasting knowledge is in `README.md` `## Notes`.

## How to work (every agent)

A parent agent runs one worker at a time, never two in parallel, and starts each with a one-line prompt: "Read and follow `foundation-todos.md` `## How to work` in <repo>; your todo: T<n>". Batch small todos into one worker; it gives one commit message per todo. Workers also follow spaces-kisd `AGENTS.md`, this repo's `AGENTS.md` and the README `## Notes` of what they change. Paths: this repo is `web/app/plugins/spaces-markup/vendor/dol-lab/foundation-sites-template` inside the site root `/mnt/Data/Local-Work/doll/spaces.kisd/spaces-kisd`. Uncommitted library changes from earlier workers are the session's own, not foreign.

1. First check `git status` and the timestamps of your target files: if they changed in the last minutes, another agent owns the todo; stop and report. Then read this repo's `AGENTS.md` (including `## Checking in Spaces` for consumer pages) and follow it; then the files your task names.
2. Hand over: delete finished items from `## Todo`, add what you could not check to `## To verify`, add new questions to `## Questions`. Edit this file with a fresh read right before the edit (others edit it too). Lasting knowledge goes where `AGENTS.md` `## Writing` says (or the consumer's README), not here. Think about how your work could have used fewer tokens; if something really helps and is simple, add it to `AGENTS.md`. If you spent many tokens on something a tooling change would fix (a missing script option, shot state, recipe), put it in your final reply as a proposed todo; the parent adds it to the top of `## Todo` if viable.
3. Print one-line commit messages per repo (`type(<plugin or theme>): …`). Staging per spaces-kisd `AGENTS.md`: never stage this file; stage your files only if that repo's index is empty, otherwise leave them unstaged and say so; `vscm` only if you staged. `composer lint -- <php paths>` for PHP you touched. Never commit. Final reply, at most 6 lines: what changed per repo, checks, commit messages, staged or not, token-saving line, anything to decide. Stop.

## Saving tokens (parent)

- Turn a worker's proposed token-saving todo into a todo at the top of `## Todo` if it is viable.
- Batch small todos into one worker: each worker first spends about 20k tokens on mandatory reading (spaces-kisd `AGENTS.md`, this file, README `## Notes`), plus its system prompt.
- Relay only decisions, open checks and commit messages to the user, not the whole report: every parent turn re-sends the parent's full context.
- Edit this file yourself only for short additions; let the next worker fold the rest in at its handover.
- Keep the mandatory reading short: workers grep README `## Notes` for their subject instead of reading it whole, and `## To verify` stays a list of open checks, not a log of what was done.
- Do not wait for user input if possible: when a worker finishes, start the next todo right away. Decide what you can (KISS); put what only the user can decide into `## Questions` and go on with todos it does not block.
